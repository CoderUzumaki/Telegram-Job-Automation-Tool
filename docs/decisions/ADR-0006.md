# ADR-0006: Telegram behind an application-owned port

Status: Recorded specification baseline; implementation verification pending
Owner: Project maintainer
Date: 2026-10-23
Reference: JR-002; LLD §§3,7,11,13

## Context

Preserve the approved MVP boundaries while allowing requirements and adapters to change independently.

## Decision

Application workflows depend on TelegramGateway and normalized DTOs, with Telethon confined to its adapter. Inject a fake gateway for offline tests. Discover metadata before consent; read content only from explicitly approved sources. Fence writes using permission versions. Keep authentication secrets in OS-protected storage through the host; no default plaintext session files. No Telegram-content LLM processing.

## Consequences and alternatives

Provider exceptions and SDK types must not leak into policies. Port separation supports changes without speculative additional providers. Consent does not establish content licensing clearance.

## Verification

JR-015–019 and I04/I11/I12 validate sessions, permission races, catch-up and retries; live tests need explicit account/group authorization.

## Supersession

No replacement. Material changes require a new ADR and corresponding contract/test updates.
